# Корзина Jarvis и корзина EKT

Проверено 23.09.2026. **Автоматический перенос в действующий магазин не подключён.** Кнопка открывает `https://ekt.kz/personal/cart/`; состав корзины Jarvis автоматически туда не передаётся. Для передачи списка доступны TXT-подборка и подготовка обращения менеджеру.

## Что проверено

- EKT использует отдельную браузерную сессию магазина на Bitrix.
- Публичный [скрипт интерфейса EKT](https://ekt.kz/local/templates/ekt_v2/js/costume.js) выполняет добавление через POST `/local/templates/template/ajax/ajax.php` с действием `add2basket`, ID и количеством. Это внутренний обработчик сайта, а не предоставленный партнёром API переноса.
- Проверка OPTIONS с Origin `https://jarvis-ekt.vercel.app` не вернула `Access-Control-Allow-Origin` и `Access-Control-Allow-Credentials`; ответ также содержит `X-Frame-Options: SAMEORIGIN`.
- Предоставленные реквизиты используются для чтения каталога. Документации метода импорта корзины и доступа к изменению сайта EKT нет.

Серверный запрос от Jarvis создал бы отдельную серверную сессию, а не корзину покупателя в его браузере. Поэтому интерфейс не сообщает об успешном переносе после обычного перехода по ссылке. Внешние корзины и заказы при исследовании не изменялись.

## Что нужно от партнёра для подключения

Один поддерживаемый EKT метод импорта, который принимает список `{ productId, quantity }` и возвращает короткоживущую ссылку для открытия этой подборки в браузерной корзине магазина. Другой вариант — согласованный обработчик на домене EKT, который принимает подписанный одноразовый запрос от Jarvis и применяет его к сессии посетителя.

Перед публикацией интеграции необходимо согласовать:

1. Соответствие ID каталога EKT ID товаров/торговых предложений магазина.
2. Поведение при уже существующих позициях: сложение количества или замена; без очистки чужого текущего состава.
3. Повторную проверку цены, остатков, кратности и доступности на стороне EKT.
4. Явное подтверждение пользователя, подпись запроса, срок действия и защиту от повторного применения.
5. Однозначный результат по каждой позиции; при ошибке нельзя показывать «перенесено».
6. Отдельный тестовый контур: две позиции, существующая корзина, повтор ссылки, недостаточный остаток и частичный сбой. Оформление заказа и оплата не должны запускаться импортом.

Это требования к следующей интеграции, а не описание работающего API.
